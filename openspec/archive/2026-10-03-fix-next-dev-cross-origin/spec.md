# Spec 变更: fix-next-dev-cross-origin

> **apply 说明**：本 change 的 **spec 增量为空** —— 这是**有意的**，不是漏写。
>
> **判断依据**：spec 描述的是**产品契约**（形态 / 设计系统 / API 接入 / 页面 / 静态托管），
> 而 `next.config.mjs` 的 `allowedDevOrigins` **只影响 `next dev` 开发服务器，
> 不进生产构建** —— `pnpm build:console` 的产物与它无关。
> 因此它不构成任何产品行为契约，无需写进 spec。
>
> **那为什么还要立案？** 因为它修的是一个**真实发生过的误判**
> （见 proposal：Next 16 拦截跨源 dev 资源 → JS chunk 全被 block → 页面成空壳 →
> 数据永远"加载中"，**被误归因为"后端慢"**，浪费了一整轮验证）。
> 立案是为了让下一个遇到同样现象的人**搜得到**，而不是在 `next.config.mjs` 里发现不了。
>
> ⚠️ 若将来 spec 引入「开发环境契约」一节，本条应迁入其中。

## 明确不涉及

- **不改任何产品契约** —— 见上
- **不改 §7 静态托管契约** —— 生产托管路径与 dev 配置无关
