# Change Proposal: verify-console-basics

## 元信息

- **日期**: 2026-10-16
- **类型**: DOC + TEST（**验证记录**，不改产品行为）
- **状态**: **archived**（2026-10-16 完成 propose → apply → archive；未部署）
- **影响 spec**: 无（本 change **不新增/不修改任何契约**）
- **来源**: 修复计划 §四「**保留新增前端功能的基本验证：主题切换、贴纸加载与轮换、编程入口、窄屏布局**」

## 这条要解决什么

计划要求对这四项新前端能力保留**基本验证**。它们此前**都没有自动化断言**，
只有"当初是这么写的"——而本项目反复栽的正是这一类（跨文件引用漂移、静默回落）。

所以本 change 做两件事：

1. **能自动化的，就变成会红的断言**（尤其是**跨文件一致性**）；
2. **本环境验不了的，明确写"没验"**，并写清**要在浏览器里看什么** ——
   §八 的纪律是「**未执行的测试不标为通过**」，视觉与时序类尤其不能靠推理代替。

## 做了什么（可自动化的部分）

新增 `packages/console/tests/theme-contract.test.ts`（**17 例**）。

主题 id 被**三处**引用，任何一处漂移都是**静默失效**，光看代码看不出来，所以读文件对：

| 断言 | 挡住了哪种漂移 |
|---|---|
| `layout.tsx` 内联脚本用的是**同一个** `THEME_STORAGE_KEY` | 防闪烁脚本读不到值 ⇒ 切主题后刷新会**闪一下**（spec §2 契约 5） |
| 每个 `THEMES.id` 在 `themes.css` 里**都有** `[data-theme='<id>']` 块 | 「加了新主题但忘了写 CSS」⇒ 用户切过去**什么都没变** |
| 每套主题的 `swatches.primary/accent` **必须出现在 CSS 里** | 预览色卡与真实配色不一致 ⇒ **色卡骗人** |
| 每套主题恰好一个 `--primary` + 一个 `--accent` | spec §2 契约 2（不许两套主色） |
| 默认主题是 `warm-ink` 且在列表里 | spec §2 契约 4 |
| `getTheme()` 对「无值 / 已删除的旧 id / 非字符串」一律**回落默认不抛** | 隐私模式、storage 被禁、旧版本残留 id |
| `setTheme()` 在 storage 被禁时 **DOM 照常生效**但返回 `false` | 「刷新后会回落」这件事必须能被告知 |
| 服务端渲染（无 window/document）不抛 | SSR 安全 |
| `stickerApi.fileUrl` 对**空格与斜杠**做编码 | 名字里带 `/` 会把路径拆成两段 |

## ⚠️ 本环境**验不了**的部分（明确标注，不许当成已通过）

| 项 | 为什么验不了 | **需要在浏览器里确认什么** |
|---|---|---|
| **窄屏布局** | 需要真实视口与渲染；本环境无浏览器、无截图能力 | ① `/memory` 页在窄屏下事实行不溢出、按钮不挤压；② 聊天里表情包图片（80px 固定 + `max-w-full`）不撑破气泡；③ 侧栏折叠可用 |
| **贴纸加载与轮换** | 轮换逻辑写在 `XilianFigure` 组件内部（含 7s `setInterval`），本仓**没有组件测试基建**（无 RTL）⇒ 无自动断言 | ① 大形象 7 秒换一张且**不重复**当前张；② 65 张**不预载**（只请求当前这张）；③ 固定边长 ⇒ 换图**不引起布局跳动**；④ `prefers-reduced-motion` 下不淡入 |
| **编程入口** | `/code` 页存在且能静态生成（构建已验证 ✅），但**引导文案与 `dsh://` 按钮**的正确性属内容 | ① 未装 dsh 的机器上点按钮有明确提示（不是"没反应"）；② 讲清"去哪儿/为什么/没装怎么办" |
| **表情包渲染的交互** | 同上（无 RTL） | 发一条带 `[表情包:开心]` 的消息，确认：图片出现在**句子中间**、**流式期间不闪半截标记**、**名字不存在时显示名字片**而不是破图 |

★ 这四项**不是"大概没问题"**，而是**本轮没有验证**。本文件的用途就是让"没验"这件事
**可见、可接手**，而不是留在某个人的记忆里。

## 设计决策

### D1 只加测试与记录，**不改任何产品代码**

`verify-*` 类 change 的价值在**把既有承诺固化成断言**；顺手改代码会让
"验证"与"改动"混在一起，反而说不清哪条断言是在验旧行为还是新行为。

### D2 跨文件一致性用**读文件**断言，不用运行时断言

主题的三处引用在**构建期就可能漂移**（CSS 与 TS 是两种文件）。
运行时断言（比如"切过去看看变没变"）在这里既做不到也不可靠；
直接读 `themes.css` / `layout.tsx` 的文本对字符串，是最贴近故障形态的判据。

**被否决：把 CSS 里的色值 import 进 TS** —— 那要改造构建链（CSS 变量 → 模块），
收益（少一处复制）远小于代价，且会让 `themes.css` 不再是可手改的真相源。
