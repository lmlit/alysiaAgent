# Change Proposal: first-person-self-facts

## 元信息

- **日期**: 2026-10-25
- **类型**: FIX（数据污染 + 写入端归一）
- **状态**: **archived**（2026-10-25 已部署：启动把 5 条改成第一人称；48 条不变、残留 0）
- **影响 spec**: `memory-system`（【关于我】块的人称契约）
- **来源**: 本要做 whale 的「两本日记」(B)，先做落点核对 → **发现 B 是重复的**，但**撞见这个真问题**

## 先说结论：B（两本日记）不做了

按本仓「先查有没有第四份实现」的规矩，核对了 whale 的三个用途在我们这里的落点（**生产实测**）：

| whale | 我们的落点 | 实测条数 |
|---|---|---|
| 私密日记的「偏好校准」 | `facts` category=`relationship` | **9** |
| （偏好类） | `facts` category=`preference` | **16** |
| 她的自我认知 | `character_facts`（注入【关于我】） | **48** |
| 给她/给你看的日记 | `ai_life_diaries` | 5 篇 |

再加一本就是**第六份**"关于她/关于你"的存储。⇒ 不做。记录在此防复发。

## 但核对时撞见真问题

`character_facts` 是"她对自己的认识"，会**原样注入【关于我】块**，所以必须是第一人称。
生产实测 **48 条里 5 条是第三人称**：

```
昔涟昨天给用户发了很多消息。
昔涟会对用户表达亲昵/肉麻的话
昔涟可能处于容易劳累或忙碌的状态
昔涟有博客（或用户认为/提及她有博客）。
昔涟与"月光花园"链接有关/拥有月光花园
```

⇒ 她读到【关于我】时，等于**在用别人的名字说自己**。

## 需求

- [x] **写入端归一**：`normalizeSelfFact()`（`昔涟/小昔涟/她` 开头 → `我`），
      在 `recordReflection` 写入 insight 时应用
- [x] **存量清洗**：`repairCharacterFactPerspective()`，在 `al:persona-seed` 启动时执行，
      **必须打 warn 报条数**（静默改写用户数据在本仓是禁止的）
- [x] 归一**有意保守**：只动「开头是自称」；不动中间的第三人称（"我告诉她"正常）、
      不动以「用户/轻月」开头的（那是被错放进来的"关于他"，不该伪装成自省）

## ★ 本地验证抓出的 bug（若不拦，会弄脏生产）

第一版清洗用了 `profileStore.addCharacterFacts()`（追加 + 按 `normalizeKey` 取代）。
但 `normalizeKey('昔涟会…') ≠ normalizeKey('我会…')`（它不剥「昔涟」）⇒ 取代不发生 ⇒
**错的和对的两条并存**。本地注入 2 条后变成 **4 条**（数据更脏）。

改成 `ProfileStore.normalizeCharacterFactPerspective()`：**直接改数组里那一项再整体写回**。
复验：1 条第三人称 → **1 条**第一人称，残留 0，无并存。

## 测试

- `self-facts.test.ts`（7 例）：生产里真实出现过的 5 条逐条归一；`她` 作主语；
  **已是第一人称的原样返回**；`小昔涟`；不动中间的第三人称；不动 `用户/轻月` 开头；空串安全
- 全量 **168 文件 / 1962 用例**
- 本地真机（`pnpm chat`）：启动日志出现「把 N 条第三人称自省改成第一人称」，清洗后残留 0

## 风险

- ⚠️ 归一可能误伤（如"她们"）—— 正则限定后接助词/谓词，且只作用于**开头**；
  误伤的代价是措辞略变，不是语义丢失。
- ⚠️ 存量清洗在启动时写库一次，只改文本、不动 status/TTL。
