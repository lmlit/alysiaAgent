## 动机（为什么做）

**用户原话**：「你看看我们现在的网站，感觉有点怪怪的：…这里应该只放上线的，
还有就是，有些是作为**子页面**的吧，**比如昔涟的日记**」。

当时的基站首页把 `public/` 里**每一个 `.html` 平铺成一张卡**，于是：

```
海岛的一天 / 电梯还没来 / 候车厅的下午 / 慢时钟 / 月光花园   ← 同一个站里的 5 页
把一天收好 / 等一盏灯… / 迷迷的午睡 / 窗台上那盆绿 / 早上那十分钟 / 关于我 / 昔涟·写字的地方
```

看起来像**十二个互不相干的网站**，而真实结构是**两个站、各带若干子页面**。
"日记"是「写字的地方」里的文章，不该跟站点本身并列。

## 需求（做什么）

- [ ] 首页**一级 = 站**：一个已发布项目一张卡（站名 = `public/index.html` 的 `<title>`、
      项目 id、页数、最近更新时间），点击进该站首页 `/p/<项目>/`
- [ ] **二级 = 站内页面**：卡片下方一排小链接（`首页` 在最前，其余按修改时间新→旧）
- [ ] 判据不变：站 = `public/index.html` 存在（契约 34）；未发布项目仍不上首页
- [ ] `/pages`（契约 38d）保持原样：全部产出（含预览）的流水清单

## 设计决策（怎么做，含备选与取舍）

1. **为什么把站内页面铺在卡片上、而不是只给一个"进站"链接**：
   2026-10-18 那次改成"按页列"，起因正是用户说「基站列表没有更新」——
   她加了 `slow-clock.html`，但站的首页没有导航，于是**新页看不见**。
   所以站内页面必须**自动列出来**，不能指望她维护站内导航。
2. **备选（否）**：首页只放"站"、子页面完全靠站内导航 —— 会重现"新页看不见"。
3. **备选（否）**：给每个站生成一个 `/s/<id>` 清单页 —— 多一层跳转，而卡片里已经放得下。
4. **站名取 `public/index.html` 的 `<title>`**（与页面标题同源）；取不到退回项目 id。
5. **不合并 `/pages`**：一个是"门面（已上线、按站）"，一个是"账本（全部产出、按时间）"，
   面向的问题不同，硬合并会让两边都说不清。

## 对账方向确认

- [x] 与既有契约 33/34/36 不冲突（子路径与符号链接都不动），只是**首页的信息层级**改了
- [x] 涉及 Web API？否
- [x] 涉及她的文档（`AGENTS.md`）？**否** —— 她看到的地址（`/p/<id>/<file>`、`/w/…`）一个都没变
