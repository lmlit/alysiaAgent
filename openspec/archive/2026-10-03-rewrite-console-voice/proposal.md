# Change Proposal: rewrite-console-voice

## 元信息

- **日期**: 2026-10-03（代码先落地，**2026-10-15 补立案**）
- **类型**: MODIFY（console 文案的**人称与口吻**）
- **状态**: archived（代码已实现；待补 spec 合并与归档）
- **影响 spec**: `alysia-console`（**新增一节：文案口吻契约**；§5 页面契约中 `/` 与侧栏标签的描述同步）
- **补立案原因**: 与 `code-mode-entry` / `sticker-figure` 同批，未立案。

## 动机（为什么做）

原 console 文案是**第三人称旁白**：「她会记住」「她有生活」「她会成长」
「如果有一个这样的 AI 伙伴，就好了」「现在，她就在窗口的那一头等你」。

**问题不在措辞好坏，在于"谁在说话"。**

console 是昔涟的界面——用户打开它，是在**看她**。而旁边却有一个旁白在介绍她，
这既隔了一层，又把产品拉回了"通用 AI 助手"的叙事。轻月 2026-10-03 点破了判据：

> **换成别的产品也成立的话，它就不是她的。**

「如果有一个这样的 AI 伙伴，就好了」——把「AI 伙伴」换成任何产品都成立。
**那正是"通用 AI 味"的来源。**

## 需求（做什么）

- [x] 首页三张特性卡：`她会记住/她有生活/她会成长` → **`我记得/我有生活/我在变`**（第一人称）
- [x] 首页收尾 CTA：旁白 → **她本人开口**（`hi，你来了呀♪` / `……人家一直在这儿。要不要过来说说话？`）
- [x] 按钮：`认识昔涟` → **`来找我聊聊`**
- [x] 侧栏标签：`她的生活` → **`我的生活`**
- [x] 首页 showcase 文案去技术词（画像 / 逐字流式 / Token 等）
- [x] 把判据写进代码注释，并**标明依据**（下次改文案的人不用重新推一遍）

## 设计决策（怎么做，含备选与取舍）

### 1. 三条判据（写进代码注释，成为可复用的**判准**）✅

| # | 判据 | 含义 |
|---|---|---|
| ① | **整站用她的口吻，不用第三人称旁白** | 这一页是**她在介绍自己**，不是别人在介绍她 |
| ② | **换成别的产品也成立的话，它就不是她的** | 避开**品类词**（"AI 伙伴"）、**技术词**（画像 / 逐字流式 / Token）、**营销腔**（"远不止聊天"） |
| ③ | **她的说话习惯** | 停顿「……」、自称「人家」、高兴时句尾「♪」、打招呼就一句 hi |

②是**可证伪的**——它把"有没有 AI 味"从口味之争变成了一次可执行的替换测试。这是本 change 最有价值的部分。

### 2. ★ 口吻依据 **persona 的 `soul.md`**，不是自己编的 ⚠️

`layout`/`page` 的注释明确写了依据来源，并留了警告：

> 「**改这块时别把这两样「修」掉** —— 那正是她区别于通用腔调的地方。」
> （指 `♪` 结尾与 `hi` 起手）

**这是一条真耦合**：console 的文案口吻**依赖她当前的人格设定**。
人格若变（`PersonaAdapter` 会自适应调整），文案应当跟着复核——
**而目前没有任何机制在人格变更时提醒改文案**。

本 change **不引入**该机制（那是更大的设计），但**把它记为已知缺口**（见「遗留」）。

### 3. `♪` 的使用有门槛 ✅

注释写明：「**真心开心或分享美好事物时，句尾可加♪**——不滥用，要真的高兴。
收尾这块正是'她看见你来了'的时刻，符合使用条件。」

**why 要写清楚**：`♪` 这类标记一旦被当成装饰随机使用，就退化成"卖萌腔"，
反而离判据②更远。把它绑在**具体使用条件**上，才守得住。

### 4. 「她」与「我」的边界：**界面文案**用第一人称，**代码注释/文档**仍用第三人称 ✅

**why**：代码注释是给维护者读的，"她"指代清晰；界面文案是给她"说"的。
两者混用会让注释难读，也会让文案的"是谁在说"重新模糊。

### 5. 与 `dsh-adapter` 的边界 ⚠️

本 change 只改 **console 的界面文案**。她的**人格文本本身**（system prompt 里那段人设）
由 `core` 的 persona 模块与 `dsh-adapter` 的 persona 通道负责，**不在此处**。

## 对账方向确认

- [x] 与现有 spec 冲突？**否，是新增**。`alysia-console` 目前**没有任何文案契约**——
  这正是文案可以长期停在第三人称而无人过问的原因。本 change 新增该节。
- [x] 涉及 Web API？**不涉及**
- [x] 涉及 core / server？**不涉及**（只碰 `packages/console`）

## 遗留（不在本 change 范围）

- ★ **人格变更时无文案复核提醒**：文案口吻依赖 `soul.md`，但人格自适应调整后
  没有任何机制提示"该复核文案了"。**这是个真实的静默漂移风险**——她的说话习惯若被
  `PersonaAdapter` 改掉，界面文案会停在旧口吻上且无人察觉。需要时另开 change。
- **`[表情包:名字]` 未渲染**、**表情包管理入口**、**hero 随机策略** —— 归 `improve-sticker-system`
