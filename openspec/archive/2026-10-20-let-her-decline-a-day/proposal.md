# Change Proposal: let-her-decline-a-day

## 元信息

- **日期**: 2026-10-20
- **类型**: FEATURE（行为变更：她获得"不主动"的权利）
- **状态**: `applied`（proposal 与 apply **同轮完成** —— 用户当日拍板后直接实现，如实记录在此）
- **影响 spec**: `ai-life-system` **§11.2（新增）** + §2「锁续期」行澄清
- **用户原话**: 「**可以拒绝**」（2026-10-20）

## 这条要解决什么

spec §2 的 `P1-6「锁一定续，永不静默停摆」`把「不主动」定义成**故障**：

> 每次触发=锁续期：成功按模型建议 / 失败 1h 保底 / 异常 try-catch 兜底 —— 锁一定续，永不静默停摆

这条本意是**稳定性**（线上真出过锁断掉、她再也不醒的事故），
但它的副作用是：**系统到点就必须产出一条内容**。
于是她连「这一轮不想说话」都没有表达渠道 —— 那不是稳定，是**只许表演**。

## 关键判断：P1-6 要保留，但它管错了对象

| | P1-6 该防的 | P1-6 不该防的 |
|---|---|---|
| 是什么 | **生产故障** —— LLM 失败 / 锁断 / 进程停 | **她的意愿** —— 这一轮不想开口 |

所以本 change 的形态是：**调度永不静默停摆（P1-6 原样保留）+ 她可以选择这一轮不出声**。
两者不矛盾，因为拒绝路径**照样续期锁、照样留痕**。

## 需求

1. `LifeService.maybeDecline()`：在生成事件**之前**判定（tick 的 ③-pre）
2. 拒绝时：生成理由 → 写 `internal` 事件（`origin='decline'`，前缀「（这一轮没说话）」）
   → 续期锁 → 结束本次 tick。**不推送、不占配额**
3. 四条护栏（缺一个都会变成"她从此不说话了"）：

| 护栏 | 值 | 理由 |
|---|---|---|
| 触发概率 | `declineChance` 缺省 **0.15** | 事件节奏 0.5–8h 一次，不是每天一次；30% 会太频繁 |
| 连续拒绝上限 | **2** | 到顶强制说话 |
| 理由最短 | **6 字** | 「算了」不算理由 |
| 失败处置 | **fail-open** | 拿不到理由 ⇒ 退回正常生成。**拒绝机制坏了不许表现为"她沉默了"** |

4. 提示词 `LIFE_DECLINE_PROMPT` 三条约束：具体 / 不道歉不补偿 / 不向用户喊话
5. 可整体关闭：`declineChance <= 0` 或未注入 `generateDecline`

## 不做什么

- **不改 `P1-6` 的续期行为**（锁照续，保底照旧）
- 不做「今天一整天不醒」——我们的调度单位是**一轮事件**，不是一天
- 不推送「她今天不想说话」给用户（那是她自己的记录，报备会变成索要安慰）
- 不改 Web/console（理由在生活事件流里本来就看得到）

## 对账方向

P1-6 是**doc 措辞过宽**（把「故障」写成了「一切不主动」），不是 impl 违约 ⇒
**澄清 doc 的适用范围**（§2 那一行 + §11.2），不动 P1-6 的机制。
