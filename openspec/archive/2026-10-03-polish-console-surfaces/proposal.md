# Change Proposal: polish-console-surfaces

## 元信息

- **日期**: 2026-10-03（代码先落地，**2026-10-15 补立案**）
- **类型**: FIX（表面效果不可见的参数问题）+ MODIFY（改用主题变量）
- **状态**: archived（代码已实现；待补 spec 合并与归档）
- **影响 spec**: `alysia-console`（§2 设计系统：补「效果参数必须真的能被看见」这条判准；毛玻璃取值）
- **补立案原因**: 与 `code-mode-entry` / `sticker-figure` / `rewrite-console-voice` 同批，未立案。

## 动机（为什么做）

三处改动，**同一个病根**：

> **用户以为功能没了，其实东西都在，只是参数让它看不见。**

| 症状（用户原话） | 真实原因 | 修法 |
|---|---|---|
| 「**毛玻璃没了**」 | 侧栏 `bg-sidebar/95` 只透 5%，模糊**几乎没有可显形的对象** | 95% → **80%**，`backdrop-blur-xl` → `2xl` |
| 「**水波没了**」 | ripple 触发阈值 42px / 55ms 太严 —— **慢慢挪鼠标完全不出涟漪** | 42px/55ms → **26px / 42ms**（尺寸 18+0.5s → 20+0.55s） |
| 切到 sakura 后「**满地还是暖金**」 | ripple 描边写死 `oklch(0.83 0.12 72)`，**没接主题变量** | 改用 `var(--primary)` / `var(--accent)`；同时提高对比（原描边 55% 在深底上太淡） |

**共同教训**：这三处都不是"功能坏了"，而是**参数把功能藏起来了**。
排查时若只看"代码在不在"，会得出"功能正常"的错误结论——
**必须看"它在用户那儿是否真的可见"**。

## 需求（做什么）

- [x] 侧栏毛玻璃：`bg-sidebar/80` + `backdrop-blur-2xl`（原 `/95` + `blur-xl`）
- [x] ripple 触发阈值放宽：`dist < 26`、`now - t < 42`（原 `42` / `55`）
- [x] ripple 粒子尺寸：`20 + speed * 0.55`（原 `18 + speed * 0.5`）
- [x] ripple 配色改**主题变量**：`color-mix(in oklab, var(--primary) 85%, transparent)` 描边；
      径向渐变用 `var(--primary) 30%` + `var(--accent) 14%`（原为写死的两组 oklch 暖金/暖橙）

## 设计决策（怎么做，含备选与取舍）

### 1. 毛玻璃：**提高透明度**而不是提高模糊 ✅

**why**：`backdrop-blur` 作用于**背后透出来的内容**。95% 不透明时背后几乎没有内容，
**模糊再强也无对象可模糊** —— 直觉上"加大模糊"是错的修法。

**被否决**：只把 `blur-xl` 提到 `2xl` —— 治不了本，因为瓶颈在透明度不在模糊半径。

### 2. ripple 阈值放宽而非"提高灵敏度开关" ✅

**why**：阈值存在的意义是**节流**（避免密集生成粒子拖慢页面），不是"筛选快速移动"。
42px 这个值把**慢速移动**整个排除了——而那恰恰是最常见的移动方式。

**被否决**：加一个用户可调的灵敏度设置 —— 为一个小众手感问题引入配置项不划算。

### 3. ripple 改用主题变量（与 `add-theme-system` 同向）✅

**why**：`add-theme-system` 立的契约是「组件一律只读语义变量」。
ripple 是**唯一漏网的一处写死色值**——它在默认主题下看不出来，
**切到 sakura 才暴露**（暖金涟漪配粉紫界面）。

**顺带修对比度**：原描边 `55%` 在深底上太淡，注释写明"看着像没画出来"。
改用 `85%` 的 `color-mix` 后对比明显。

> ★ 这条改动**与 `add-theme-system` 有重叠**（都是"接主题变量"）。
> 归属说明：**变量接入本身属 `add-theme-system` 的契约范围**，本 change 收的是
> "它同时顺手修了对比度"这部分。两者**同批发布**，无先后依赖。

### 4. 为什么值得单独立案（而不是塞进 `add-theme-system`）✅

三条改动的**判据**是同一条 —— **"效果参数必须真的能在用户那儿显现"** ——
而这条判据 `add-theme-system` 不覆盖（它讲的是色板可扩展，不是效果可见性）。

把它单独记下来，是为了**下一个调效果参数的人**能看到这条先例：
**别只看代码在不在，要看它在默认参数下是否可见。**
