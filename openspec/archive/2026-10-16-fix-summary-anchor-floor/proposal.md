# Change Proposal: fix-summary-anchor-floor

## 元信息

- **日期**: 2026-10-16
- **类型**: FIX（修静默永久丢失；**刻意修订两条既有测试的契约**）
- **状态**: **archived**（2026-10-16 完成 propose → apply → archive；未部署）
- **影响 spec**: `memory-system` §5.4.1（摘要窗口契约）
- **来源**: `docs/KNOWN-ISSUES.md` **KI-26**（跑真实 e2e 时暴露）；用户 2026-10-16 选定「修锚点」

## 这条要解决什么

**「会话没有历史摘要 + 消息全部早于 24h」⇒ 那批消息永远进不了摘要。**

`MemoryManager.summaryAnchor()` 在「这个会话还没有上一份摘要」时用
`Date.now() − 24h` 当窗口下界 ⇒ 更早的消息一条都看不见 ⇒ `no-events` 直接返回。

**而且永远够不着**：下一次的锚点是「上一份摘要的 `ended_at`」——可上一份**根本不存在**
⇒ 每回都退回 `now − 24h`，而 now 还在往前跑。

**真实场景**：会话开着超过 24h 才结束（dsh 长会话 / QQ 群持续几天的会话）、
或进程停过一段时间后由 `archiveStaleSessions` 归档 ⇒ **最老那一段永久丢失**。
属 KI-24「永久不进摘要」同一族。

**取证**（真实 e2e + 单测）：把会话事件的时间戳放到 24h 以外即稳定复现。
最刺眼的一条是**同一会话内部**的截断：

```
× 同一个会话里，跨过 24h 线的那段也要摘进去
  AssertionError: 只摘了最近的，早于 24h 的那段被丢了:
    expected '[用户] 刚刚说：今天在看生命周期…' to contain '我在学 Rust'
```

## ⚠️ 本 change 最重要的一点：**旧行为是事故对策，不是疏忽**

`session-end-window.test.ts` 的文件头记着 **2026-10-11 的线上事故**：

> 202 条摘要里 **153 条（76%）窗口跨度 > 24h**，**29 条恰好 `message_count = 1000`、
> 跨度 46~61 天**，同一段历史被反复摘要（45 秒内连摘三次），摘要槽稳定失败
> （8 天 10 次空响应 + 4 次 truncated）。

⇒ 那两条测「无历史摘要 → 仍回退 24h」的用例**是在守那个事故**。
**所以在动手前必须先判断：去掉 24h 会不会把事故重新造出来。**

**判断结论（决定性的）**：事故的**真机制**是
「三个 SessionEnd 入口**都没传锚点** ⇒ 落到 `getBySession` 缺省的全历史
⇒ **同一段历史被反复摘要**」。坏窗口（46~61 天 / 1000 条）是它的**症状**，不是病因。
那个机制已被「锚点只此一处（2026-10-11）+ **摘完就前进**（本 change 第 2 条测试锁住）」堵死
—— 从头摘只会发生**一次**。

**而 24h 兜底的代价是静默且不可恢复的丢失。**
权衡：一次**可见且可重试**的大窗口（失败写成 `summary_status='failed'`，
`retryFailedSummaries()` 会补 —— 这两个机制都是 2026-10-11 之后才有的）
**优于**永久丢失。

## 需求（做什么）

- [ ] **R1**：从未摘要过的会话 → 下界 = **该会话最早的事件**（不再用 `now − 24h`）
- [ ] **R2**：下界**必须减 1ms** —— 窗口是**排他**的（`created_at > since`，§5.4.1 契约 4b），
      否则"从头摘"会**正好漏掉第一条**（红测抓到过：新鲜会话因此一条摘要都不产）
- [ ] **R3**：**已有历史摘要 → 仍严格从 `ended_at` 之后**（**绝不**回头重摘）
- [ ] **R4**：有会话记录但 `ended_at` 为空 → **保守到底（仍是 24h）**，
      **不跟着放宽**：那个分支没有已知边界，而窗口放宽多少就可能重摘多少
- [ ] **R5**：**三条入口同规则**（`onSessionEnd` / `extractProfile` / `archiveStaleSessions`）
- [ ] **R6**：**刻意修订**那两条事故守卫测试，并把"守卫本身不丢"用更强的判据补回来
      （见下 R7）
- [ ] **R7**：新增测试**直接锁住事故不会复发**：摘过一次之后，第二次调用
      **绝不**重摘同一段历史

## 设计决策（含被否决的方案 —— 这一节是本次最值钱的部分）

### D1（最终采纳）**不设时间上限**，从头摘

理由见上「事故的真机制」。补充两个边界：

- `getBySession` 有 `LIMIT 1000` ⇒ 单次窗口在**条数**上仍有界（不是无界）；
- ⚠️ **残留风险（如实记）**：从未摘过且超过 1000 条的会话，最老那批**这次仍够不到**，
  而新摘要的 `ended_at` 会把它们挡在后面 ⇒ 那部分仍会丢。
  **彻底做法是分块回填**（Backlog「历史画像回填」，需评估成本与副作用），**不在本 change 内**。

### D2 ❌ 被否决：保留 24h 兜底

就是现状（KI-26），等于默认接受静默永久丢失。

### D3 ❌ 被否决：加一个「有界的从头摘」（例如 `now − 7d`）

**我一度实现了它并跑通了 core 全套（757 绿），随后自己推翻了。** 记录在这里防止后人重走：

- 它**无法覆盖事故自己的症状场景**：e2e 里那两个"会话结束得太晚"的用例，
  事件时间戳距今**三个半月**，任何有限上限都会把它们挡在外面
  ⇒ 真实 e2e 仍是 3/5（我实测确认过）；
- 上限是个**没有依据的魔数**：写 7 天就要解释为什么不是 3 天或 30 天；
- 它把"永久丢失"换成了"**小声**的永久丢失"（warn 一次），
  而 KI-26 的教训恰恰是**静默**最危险；
- 而它想防的那个形态，**已经被 R7 的判据真正防住了**（摘过就前进）。

⇒ 结论：**上限防的是一个已经不存在的问题，代价却是真的丢失。**

### D4 ❌ 被否决：把 `getBySession` 改成按 `processed` 过滤（用位标记防重摘）

看起来更"正统"，但会**改变窗口语义的根**：`processed` 位是三段管线共用的
（`PROCESSED_PROFILE` / `PERSONA` / `SUMMARY` / `KNOWLEDGE`），按它过滤会让
「谁处理过哪一位」变成窗口可见性的一部分 —— 那是另一层耦合，
且会让 §5.4.1 那套 `(since, until]` 游标语义失去意义。本 change 不动它。

## 对账方向确认

- [x] 与现有 spec 冲突？——§5.4.1 只声明了「窗口右边界是数据边界（`ended_at`）」，
      **未声明**「无历史摘要时下界取什么」。本 change **补契约**。
- [x] 方向判断：**缺陷**（行为造成静默丢失）⇒ **改 impl + 补 doc**。
- [x] 涉及 Web API？——**不涉及**（`extractProfile` 的行为随之改善，签名不变）。
- [x] ⚠️ **改了两条既有测试**：它们编码的是**事故对策**，所以本 change 把它们改成新契约，
      并在测试文件里写清"为什么原来那样写、为什么现在这样写"（**不删除守卫，只换更强的判据**）。

## 测试计划

| 编号 | 场景 | 验收 |
|---|---|---|
| S1 | **主症**：消息都是 3 天前 + 从未摘要过 | **必须**产出摘要与 facts（旧实现：0） |
| S2 | **同一会话**跨过 24h 线的那段 | 也要进摘要（旧实现：只摘最近一段） |
| S3 | 已有历史摘要 | 严格从 `ended_at` 之后；**不含**已摘过的旧内容 |
| S4 | 有记录但 `ended_at` 空 | **保守**：不重摘整段历史 |
| S5 | 新鲜会话 | 行为不变 |
| S6 | 10 天前 + 从未摘要过 | **也要**摘（不设时间上限） |
| S7 | **★ 摘过一次 → 第二次绝不重摘**（事故形态不复发） | 第二次只含新消息 |
| S8 | cron 路径（`archiveStaleSessions`） | 与 session-end **同规则** |
| S9 | 真实 e2e（`cron` / `real-api`，**用例一行不改**） | 转绿 |

## ⚠️ 动手前的提醒

- **别把「排他下界」忘了**（R2）：减 1ms 不是凑数，`created_at > since` 会吃掉第一条。
- **别在 `ended_at` 为空的分支上顺手放宽**（R4）：那里没有已知边界。
- **别拿「46~61 天 / 1000 条」当时事故的病因**：病是**反复摘要同一段历史**，
  而它已经被"摘完就前进"治住了（S7 锁住）。
