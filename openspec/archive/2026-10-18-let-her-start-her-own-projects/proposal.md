# Change Proposal: let-her-start-her-own-projects

## 元信息

- **日期**: 2026-10-18
- **类型**: NEW（自主性 + 成本/边界护栏）
- **状态**: archived
- **影响 spec**: `project-tasks` §16（新增）+ §11（补充预览服务线程化）
- **前置**：`gate-project-tasks-to-offpeak`（窗口）、`give-author-eyes`（相机）、`add-preview-hub`（基站）

## 动机（用户原话）

> 「让她的生活/主动事件系统也能发起"做网站"（比如她自己在 idle 时决定做个小页面）」

## ★ 这个功能的难点不是"能不能"，是**边界**

她能自己发起，就意味着三件事同时发生：**花真钱**、**在她的工作区写文件**、**可能改变对外可见的东西**。
所以设计里每一条都在挡这三种风险：

| 风险 | 护栏 |
|---|---|
| 花钱 | 只在**空闲时段**（复用 §14 的窗口）；**每天最多 1 次**；两次之间 ≥24h；**有在途任务就不做** |
| 写错地方 | **必须显式配置 `projectId`** —— 留空就**不发**（见下方真机事故） |
| 偷偷上线 | **默认 `allowPublish: false`**：她可以决定做什么，但"上线"留给对话里的人 |
| 用户还在 | 用户 `minIdleHours`（默认 6h）内说过话就不做 —— **用户在的时候应该陪用户，不是跑去干活** |

## 设计决策

### 1. 决策抽成纯函数，不埋在定时器里

`decideSelfActivity()`（`core/memory/self-activity.ts`）：输入现状、输出 `{proceed, reason, detail}`。
理由：这些规则每一条都在花钱、都改可见状态 —— 不能靠"跑一阵看看有没有乱发"来验。

### 2. 她自己说"想做什么"（走人格，但只给事实与边界）

`composeSelfActivityIdea()`：给能做/不能做的清单（纯静态、零外链、规模小），不给审美要求。
⚠️ `max_tokens` **必须给足**：第一次用 200 时返回空串（reasoning 吃光预算），
就是 KI-1 那个形状。现在 800。

### 3. 结果照旧走"回执 + 推送"

`originSessionId` = 用户私聊会话 ⇒ 她做完会**自己告诉用户**（§10/§15 那套）。
`origin = 'self'`（新增取值），与 `user` / `delegated` 区分。

### 4. 去重靠 requestKey，不靠"只跑一次"

`self:<日期>:<项目>` ⇒ 定时器抖了、容器重启了都不会重复建任务。

### 5. 顺带修的相邻问题：预览服务是**单线程**的

真机上出现**间歇性 `000`**（`Recv-Q 6`）。根因：服务器 python 是 **3.6**，
`http.server` 在 3.6 **还是单线程**（3.7 才默认线程版）。她自己截图 + 用户浏览器 + 基站同时取页面时就排队。
⇒ 换成 `scripts/preview-serve.py`（`ThreadingMixIn`）。
⚠️ 同一处还踩了两个 3.6 兼容坑：`directory=` 参数是 3.7 才有的；越界防护**不能**用 `realpath`
（`p/<项目>` 本来就是符号链接，会被误判成越狱 ⇒ 页面回落成基站首页）。

> ⚠️ **治理说明**：这个预览服务修复与"自发起"是两件事，我在同一个 change 里交付了。
> 按 `openspec/project.md` 应该分开；记在此处，不为它找理由。

## 真机事故（两条，都写进 tasks）

1. **`provides: false` + `ctx.provide()` ⇒ apply 失败 ⇒ 整个 Alysia 起不来 ⇒ 容器重启 7 次**
2. **落错项目**：先前"留空 = 用登记列表最后一个"⇒ 她落到 `alysia-blog`（精心做的「关于我」页），
   一个验证触发的任务去改正式页面的风险不该存在 ⇒ 现在**留空不发**。
   （实测她**没**动 `index.html`（哈希一致），只新建了 `slow-clock.html` —— 运气好，不是设计好。）

## 对账方向确认

- [x] 新增 `origin: 'self'` ⇒ store 读回的同形判断要一起改（否则读回来变 `user`）
- [x] 新增配置段 `selfActivity` ⇒ `loadConfig()` 显式映射（这个坑踩过两次）
- [x] 新增模块 `al:self-activity` ⇒ **必须声明 `provides`**（见事故 1）
