# Change Proposal: add-preview-hub

## 元信息

- **日期**: 2026-10-18
- **类型**: NEW（展示层：一个总入口）
- **状态**: **archived**（2026-10-18 归档；T1–T5 完成，公网验证）
- **影响 spec**: `project-tasks`（新增 §11）
- **前置**：`harden-delegated-runtime`（工作区在 `/srv`、执行体非 root）

## 动机（用户原话）

> 「现在她做的东西给我们展示只有通过一个链接，只能展示一个东西，我们是不是可以搞个**基站**，
> 里面嵌套她做的网页呢」

问题是真的：一个项目一个地址、每加一个就得有人给她一个新链接 —— **没有"她做过的事都在哪"这个地方**。

## 需求

- [ ] `/` 变成**总入口**（基站），列出她**所有**已发布的页面
- [ ] 每个项目在自己的子路径下：`/p/<项目>/`
- [ ] **自动**：她发布完就出现（<10s），下线/改名自动消失
- [ ] 她**不用**维护基站（否则一定会腐烂：新的忘了加、删的没删）
- [ ] 不破既有边界：她仍只能写自己工作区的 `public/`

## 设计决策

### 1. 生成式基站，而不是手写首页

`scripts/preview-hub.py`（root，systemd timer 每 10s 幂等跑一次）：
读 `config.yml` 的 `projects.*` → 有 `<workspace>/public/index.html` 的算"已发布" →
建 `p/<id>` 符号链接 → 生成卡片墙（标题取页面 `<title>`、时间取 mtime）。

- **原子替换** `index.html`（先写 `.tmp` 再 `os.replace`），避免读到半个页面；
- **幂等**：链接已指向正确目标就不动；
- **会删**：不再登记/未发布的链接一律清掉 —— "自动"必须包括**移除**。

### 2. 用子路径，不用 iframe

用户说"嵌套"，但 iframe 是错的容器：滚动/深链/移动端都别扭，还要和 `X-Frame-Options` 打架。
子路径 `/p/<id>/` 是**真正的嵌套**（同一站点、同一份静态服务），用户点进去就是那个页面本身。

### 3. 静态服务 serve 基站根，不 serve 某个项目的 public

`WorkingDirectory` 从 `<workspace>/public` 改为 `/srv/alysia-preview`，
`/srv/alysia-preview/p/<id>` 是指向各项目 `public/` 的**符号链接**（root 建，她改不了）。

### 4. 地址分两层，`publicUrl` 改指**具体页面**

| 含义 | 地址 |
|---|---|
| 基站（总入口） | `http://<host>:3389/` |
| 某个项目 | `http://<host>:3389/p/<项目>/` |

⇒ `projects.<id>.publicUrl` 改为后者（回执/推送带的是**她刚做的那个页面**，不是基站）。
基站地址写进她的 `.alysia-project.json` 与 `AGENTS.md`。

### 5. 不做的

- 基站**不接受她的投稿样式**（v1 用统一卡片墙）；将来可让她覆盖基站的 CSS；
- 不做缩略图/截图（没有渲染链路）；
- 不做鉴权（这是"给人看的预览"，与站点相同的安全姿态）。

## 对账方向确认

- [x] 新增 host 侧组件（生成器 + timer）⇒ 部署 SOP 要提一句
- [x] 改 `WorkingDirectory` ⇒ **不动容器/镜像**（预览服务是 host 上的 systemd 单元）
- [x] 不新增 API 端点

## 测试计划

| 项 | 判据 |
|---|---|
| 生成器幂等 | 连跑两次，第二次不改动 `index.html` 的内容语义、链接不重建 |
| 自动移除 | 把一个项目从 config 拿掉 → 下一轮链接与卡片都消失 |
| 公网 | `/` 返回 200 且含卡片；`/p/alysia-blog/` 与 `/p/alysia-blog/style.css` 均 200 |
| 她的契约 | 以 `alysia-runner` 跑 `./publish.sh`：四条判据全过，且打印基站与页面地址 |
| 回执 | 新任务的回执带的是 `/p/alysia-blog/`（不是基站根） |
