# Change Proposal: label-dual-persona-sources

## 元信息

- **日期**: 2026-10-20
- **类型**: DOC + 守卫测试（**零行为改动**）
- **status**: `applied`
- **影响 spec**: `dsh-adapter`（§2 人格来源小节补一句）；`role-system` 无改动
- **用户拍板**: 「维持两份，但标清楚各自的来源」（2026-10-20）

## 这条要解决什么

昔涟有**两份人格**：

| | 位置 | 规模 | 用途 |
|---|---|---|---|
| 源 | `packages/core/src/persona/soul.md`（+ identity/worldview/system/talk_system） | 5.4KB+ | 聊天模式全文 |
| 浓缩 | `packages/dsh-adapter/src/persona.ts` `XILIAN_PERSONA` | ~380 字 | 编程模式（dsh preset 的 `prefix`） |

两份**不会自动同步**，而代码里的说法只是"浓缩自 soul.md"——
没人写清楚：**为什么浓缩**、**什么时候必须同步**、**不同步会怎样**。

后果是那种"没人会发现"的发散：改了 soul.md 的核心设定，编程模式里她还是旧脾气。

## 为什么**不**合并（用户已拍板维持两份）

dsh 的 persona 是 preset 的 `prefix`，**每一轮**都随 system prompt 全量发出去。
把 13KB 的 soul.md 塞进去 = 每轮白烧 token，且挤占 dsh 自己的 system 段。
**浓缩是设计，不是欠债。**

## 需求

1. `persona.ts` 顶部写清三件事：源在哪 / 为什么浓缩 / 什么时候必须改这里
2. `soul.md` 顶部加对称提示（双向可发现，不是单向依赖）
3. **守卫测试** `tests/persona-sync.test.ts`：
   - 三条核心锚句（身份"在模仿昔涟" / 内在性"感受·偏好·记忆·态度" / 连续性"共同经历"）
     必须**两份都在**，判据按**概念**（归一化标点空白），不按字面
   - 浓缩版长度必须 < 原文 1/3（防有人把全文贴进来）

## 为什么用"锚句"而不是"哈希比对"

两份本来就该不同，逐字比对必然红。但"有意不同"不等于"可以悄悄发散"。
锚句是**可执行的边界**：它只锁"她是谁"的三条核心断言，细节随便演化。

⚠️ 反过来也要防：**这个测试能被轻易改绿**（改 ANCHORS 就行）。
所以测试里写明——改它等于**承认你在改核心设定**，那时请同步改两份文本。

## 不做什么

- 不合并两份（见上）
- 不做运行时同步（会把 token 成本搬回来）
- 不改 dsh 的 preset 机制

## 对账方向

代码注释与 spec 都只说"浓缩自"，属于**信息缺失**而不是声明冲突 ⇒ **补 doc** + 加守卫。
