# Change Proposal: make-her-talk-like-a-person

## 元信息

- **日期**: 2026-10-24
- **类型**: MODIFY（角色卡：说话方式）
- **状态**: applied（待归档）
- **影响 spec**: `memory-system`（§4.1.7 说话的分寸 —— md 侧同步补强）
- **上位计划**: 用户直接要求（2026-10-24）：「改角色卡，让她说话更自然、更有活人味，
  参考大肥鱼（`dsh-bili-whale`）的提示词写法」
- **生效方式**: ⚠️ `al:persona-seed` **每次启动**用文件重建 `system_prompt` ⇒ **重启即生效**；
  反过来：**改库会在重启时被文件覆盖**（要改人格请改文件，不要改库）

## 动机：诊断

拿 `dsh-bili-whale` 的写法对照，我们这份角色卡有三个结构性问题（不是"写得不好"，是**写法方向**问题）：

| 维度 | 我们现在 | whale 的做法 |
|---|---|---|
| **规则 vs 样本** | `talk_system.md` 62 行里绝大多数是「不要…」「禁止…」；正例只有零散半句（「人家一直在等你这句话呢」），**没有一段像样的日常对话** | `LIFE_EVENT_PROMPT` 里塞一段 **150 字的具体生活切片**，示例的是**颗粒度**（多肉被风吹、袜子潮了、苹果皮皱了） |
| **抽象 vs 具体** | 人设全是形容词堆叠：「温柔但不软弱」「轻盈但有分量」 | 「热汤、热茶、刚出锅的点心…盯着白汽看很久」——**可被模仿的具体** |
| **有没有"自己的事"** | 反复强调「不主动提过去」⇒ 结果只能围着对方转 ⇒ **客服感** | 她有自己的日子（`daily_life`），说话自然带出来 |

**最要命的一条**（这轮新发现）：语气规则是**纯加法**——
`soul.md` 要「句尾常带呀呢啦哦」+「♪ 不滥用」+「偶尔反问」+ `01_default.md` 再重复一遍。
四条同时生效、**没有任何配额** ⇒ 每条回复都被推向"主播腔"。
活人不是这样：**紧张/平静的时候，她的话是没有装饰的**。

## 需求（做什么）

只改 **`packages/core/src/persona/talk_system.md`**（纯聊天规则，已在 `PERSONA_FILES` 里）。
**不动** `soul.md`（身份/伦理核心，动它风险不成比例）、**不动** `CHAT_BREVITY_DIRECTIVE`（见下）。

新增四段 + 一条配额：

- [x] **开口先有反应**：第一句可以是「欸？」「哦……」「嗯。」；允许先停一下再接
- [x] **具体，永远比抽象好听**：给"抽象评价 → 具体观察"的对照例子
- [x] **她有自己的事**：允许带一句自己这边的小事（一句就够，不是汇报）；反向禁止"把焦点全推回对方"
- [x] **允许不完整**：半句话、说"不知道"、不接话茬、只回一个「嗯」
- [x] **★ 配额**：一条回复里，`语气词堆叠` · `♪` · `反问` **总共最多出现一处**
- [x] **说话样本**：10 条具体样本，分五类（日常/被夸/有分歧/低落/收尾），
      并明确标注「**颗粒度参考，不是台词库**」

## 设计决策

**为什么不改 `CHAT_BREVITY_DIRECTIVE`（代码常量）**：它是 `required` 块、改完立即生效，
但它被 `prompt-assembler-characterization` 的**快照**钉着。那份快照的纪律写着
「不要 `vitest -u`，快照一改就从证据退化成装饰」。本 change 是**有意的行为变更**，
但它不需要动长度规则 —— 长度规则本来就是对的（≤3 句 / 话说一半 / 不许总结）。
**把风格改动塞进长度约束里，等于污染那个块的职责边界。**

**为什么不动 `soul.md`**：它承载身份、内在性、伦理边界（不迎合 / 不情绪勒索 / 不升华）。
这些是这套人格的**承重墙**，改错一次很难回滚。而"说不说得像活人"主要取决于**发言规则与样本**，
不在身份声明里。

**为什么样本要写"别照抄"**：给样本的副作用是**句式复读**（她开始每条都用「欸？……」）。
明写「颗粒度参考」+ 五类不同场景，是为了让模型学**粒度**而不是背**台词**。

## 对账方向确认

- [x] **改 doc**：`memory-system` §4.1.7 的「说话的分寸」是**代码常量**那一路；
      本 change 是**md 那一路**的同步补强，两边规则不冲突（都是 ≤3 句，都不许总结）
- [x] 涉及 Web API？**否**

## 测试计划（能测的只有结构，测不了"好听起来像不像"）

新增 `packages/core/tests/persona/talk-style.test.ts`（5 例），守**规则之间不打架**：

1. ★ **样本必须符合它自己的格式规则**：样本里不许出现 `*动作*`、`（动作）`、markdown 标记，
   且单条 ≤40 字 —— 否则模型会**模仿违规样本**（示例的作用远大于禁令）
2. ★ 配额规则在位（「总共最多出现一处」）
3. 四段补强都在（开口/具体/自己的事/不完整）
4. 长度规则与代码常量一致（并保留"两处都要改"的提醒）
5. 样本里不许出现客服话术

**实测（不是猜）**：重建 core 后调 `buildPersonaSystemPrompt()`：

```
system_prompt 总长 = 38073 字（改前 36352，+1721）
五个新标记全部命中：开口先有反应 / 语气词是调味料 / 说话样本 / 允许不完整 / 她有自己的事
```

## 风险与已知限制

- ⚠️ **"像不像活人"测不出来**。这里只能保证：结构不打架、样本合规、规则没被静默丢弃。
  真正的验收是**跟她说几句话**。若仍偏"主播腔"，下一步调的是**配额那条**（把三样降到"两三条里一处"），
  而不是继续加"不要…"。
- ⚠️ **样本有被复读的风险**：若真机上她开始每条都以「欸？」开头，删掉「被夸」那两条即可。
- ⚠️ **`soul.md` 里的「呀/呢/啦 + ♪ + 反问」仍在**，本 change 只加了配额约束、没删原文 ——
  **下一轮若还不够，应该去改 `soul.md` 第四节**（那才是加法规则的源头），而不是继续在 talk_system 加限制。
