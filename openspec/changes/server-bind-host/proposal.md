# Change Proposal: server-bind-host

## 元信息

- **日期**: 2026-09-25
- **类型**: MODIFY（配置项 + 鉴权判定依据）
- **状态**: in_progress
- **影响 spec**: `server-hardening`（§6 鉴权触发条件）、`alysia-console`（§7.1 鉴权边界）

## 动机（为什么做）

用户只想**本机使用**，却发现服务绑在 `0.0.0.0`（局域网可达），因而每次都要输 token。

根因：**绑定地址与桌面模式被耦合在一起**——

```ts
await webui.listen({ port, host: IS_DESKTOP ? '127.0.0.1' : '0.0.0.0' });
```

`IS_DESKTOP`（`ALYSIA_DESKTOP=1`）是为 Electron 桌面端设计的开关，顺带还：
跳过 IM 适配器与主动推送、且（9-24 起）把前端切回 webui。
所以本地用户**无法只要求"绑回环"**——要么继承服务器的 `0.0.0.0`，要么连带关掉 IM 与主动生活。

`0.0.0.0` 对服务器**是必须的**（Docker 容器不做端口映射就连不上），默认值不能改。

## 需求（做什么）

- [ ] `server.host` 配置项（`config.yml`），默认 `0.0.0.0` —— **服务器行为完全不变**
- [ ] 本地 `config.yml` 设 `host: "127.0.0.1"`
- [ ] **鉴权判定改为跟随绑定地址**：回环 → 免鉴权；对外可达 → 强制鉴权
- [ ] 回环识别覆盖 `127.x.x.x` / `localhost` / `::1`
- [ ] 启动日志明说：绑了哪、鉴权开没开、为什么
- [ ] `config.example.yml` 与文档同步

## 设计决策（怎么做，含备选与取舍）

**决策 1：鉴权跟随绑定地址，而不是新增一个独立开关**

备选是加 `server.requireAuth: true/false` 让用户自己配。否决原因：**两个开关可以配出危险组合**
（`host: 0.0.0.0` + `requireAuth: false` = 局域网裸奔）。绑定地址是唯一事实来源时，
"对外可达 ⇒ 必须鉴权"成为不可绕过的推论。

这与代码库既有语义一致：`IS_DESKTOP` 分支本来就是"绑 127.0.0.1 + 免鉴权"。
本 change 只是把这个语义从"桌面模式"泛化到"回环绑定"。

**决策 2：默认值保持 `0.0.0.0`**

改成默认回环会让**线上容器直接失联**。默认必须与改动前逐字节一致，本地靠配置文件显式声明。

**决策 3：不做"记住上次绑定"之类的自动推断**

显式配置，不猜。

## 对账方向确认

- [x] `server-hardening` §6 现写「服务模式强制鉴权」「桌面模式免鉴权」——本 change 把触发条件
  从"模式"改为"绑定地址"。方向：**doc 更新**（语义等价泛化，非降级）
- [x] 涉及 Web API？不涉及端点；但**改变了 `/api/*` 的鉴权前置条件**，需同步 §6

## 风险

1. **回环免鉴权意味着同机其他进程可访问**。对单人 Windows 开发机可接受；
   若将来多用户共用机器，需回到 token 模式（改回非回环绑定即可自动恢复鉴权）。
2. 用户若手动把 `host` 改回 `0.0.0.0`，鉴权会**自动恢复**（不需要记得开开关）——这是决策 1 的收益。

## 测试计划

- 单测：`isLoopbackHost` 各形态（`127.0.0.1` / `127.0.0.2` / `localhost` / `::1` / `0.0.0.0` / `192.168.x.x`）
- 单测：`resolveBindHost` 在 `IS_DESKTOP` 有无 / `config.host` 有无 的四种组合下取值正确
- 回归：服务器场景（无 `host` 配置）→ 仍 `0.0.0.0` + 强制鉴权
- 实测：本地 `host: 127.0.0.1` → `netstat` 确认只监听回环；不带 token 打 `/api/*` → 200
