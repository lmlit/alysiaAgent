## 动机

2026-09-25 线上排查发现：会话摘要**已 22 天 100% 失败**，但期间：

```
容器 healthcheck:  "Status":"healthy", "FailingStreak":0     ✅
/api/health:       {"status":"ok","uptime":2062864}           ✅
```

**所有存活检查全程是绿的。坏的不是"活着"，是"做对"。**

日志其实记了 `[WARN] [SessionEnd] summary LLM failed`，但从没变成信号，三层原因：

1. **级别错配**：19,556 INFO : 16 WARN : 11 ERROR —— warn 等于不存在
2. **被噪声埋掉**：**96.6% 的日志行是 `QQ Official`**（18,958/19,634）
3. **没有任何机制在读日志**：写文件 → 7 天轮转删除，无告警无聚合

> 一句话：**问题不是"日志没反应"，是"日志和信号之间没有连接"。**

## 需求（方向，待细化时再定）

- [ ] 采集**正确性指标**（非存活指标）：摘要成功率 / 反思成功与重试数 /
      各模块 WARN·ERROR 计数 / 生活事件日条数 / QQ 重连次数
- [ ] 形态二选一或组合：
      **A** 每日运维日报（异常以数字浮现） · **B** 阈值即时告警（如"连续 3 次摘要失败"）
- [ ] 通道：复用现有 proactive 推送。⚠️ QQ 官方有 **48h 互动窗口**约束，
      长时间无互动时主动消息发不出 → **必须有 fallback**（写进 console 界面，或退化为日志）
- [ ] **不另起进程**：在现有 server 进程内聚合即可（项目已有 `token_stats.json` 落盘先例）
