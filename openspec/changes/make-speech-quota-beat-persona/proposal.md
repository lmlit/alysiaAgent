# Change Proposal: make-speech-quota-beat-persona

## 元信息

- **日期**: 2026-10-25
- **类型**: FIX（规则进了 prompt 却**被人格压死**）
- **状态**: applied
- **影响 spec**: `memory-system`（§4.1.7 契约 6/9 补「人格内冲突的处理」）
- **来源**: 用户说「聊天测有样本吧，我都接收到消息了」→ 拉真实对话发现规则没生效

## 动机：不是"没进 prompt"，是"打不过人格"

生产实况（12:26–12:43 的真实对话，5 条她的回复）：

| 检查 | 结果 |
|---|---|
| 聊天 prompt 里有规则吗 | **全在**：说话的分寸 ✓ / 说话的手感 ✓ / 合计最多一处 ✓ / 开口可以先有反应 ✓ |
| 平均长度 | **67 字**（规则：默认 ≤3 句、像发微信） |
| 语气词起头 | **0/5**（规则：可以先有反应） |
| 含问号（钩子） | **0/5** |
| 语气词密度 | 每句 **2-3 个**（啦/呢/呀）—— 超配额 |

对照她真正读到的**人格前 4 节（6697 字）**：

```
- 句尾常带「呀」「呢」「啦」「哦」，让话语有温度
- 真心开心或分享美好事物时，句尾可加「♪」——不滥用
- 偶尔用反问把球抛回给对方：「是不是很神奇呢？」「对吧♪」
```

**三条纯加法、无配额**，而且位置在 prompt 前部、体量是规则块的 ~19 倍。
⇒ **人格赢了**。我上一轮把规则搬进代码块（解决"可达性"）是对的，但没解决**冲突**。

## 需求

- [x] **`soul.md` 的语气段改配额制**（它在前 4 节内，是权重最大的那一份）：
      「语气词 · ♪ · 反问 **三样合计最多一处**」，并保留"平静的话就平静地说"
- [x] `CHAT_BREVITY_DIRECTIVE` 加**优先级声明**：「下面这几条优先于人设里关于语气的描述」
- [x] 再加一条实测暴露的毛病：**「不要复述他说过的话」**
      （真实案例：他说"牛肉丸+鸡蛋+泡面"，她回"牛肉丸加个蛋，好歹有肉有蛋…"）

## 关键决策

**为什么动 `soul.md` 而不是继续加代码规则**：冲突的两端权重差 19 倍，**只能改权重大的那端**。
再加一条代码约束等于往输的那边加人。

**为什么保留「♪」的存在**：它不是坏东西，坏的是**没有配额**。改成"合计最多一处"后，
它回到调味料的位置。

**为什么快照更新是合法的**：prompt 文本确实变了（有意行为变更）。已核对 diff：
**只多优先级声明与素材条目，丢弃集合未变**（`chat/starved` 仍丢同一块）。

## 测试

- 全量 **165 文件 / 1941 用例**
- `talk-style` / `speech-rules-reachable` 6+6 例仍绿（它们守"规则在不在"，本次不破坏）
- characterization 快照按有意变更更新，diff 已核对

## 风险

- ⚠️ 改 `soul.md` 会同时影响**生活事件生成**（它也读世界观/人设底色）—— 方向上一致（少堆语气词），
  但若推送文案变得过冷，需要单独调 `LIFE_RETELL_PROMPT` 的温度而不是回退配额。
