# improve-sticker-system

- **状态**: proposed
- **影响 spec**: `sticker-protocol`（表情包协议，当前 frozen）、`alysia-console`

## 背景

2026-10-03 表情包素材从 13 张扩到 **65 张**（新增 52 张二创图，走服务端素材库
`data/stickers/` + 世界书 `content_type='image'` 条目，**不入公开仓库**），
`XilianFigure` 也从 Live2D 换成了表情包轮换（change: `sticker-figure`）。

**素材量变了，选择策略却还是最初那套** —— 三个问题因此开始显现。

## 现状与问题

1. **hero 是无差别随机**
   从全部 65 张里均匀抽，会抽到「どうして?!」这类情绪强烈的图，
   放在"打招呼"的位置观感会突然跳一下 —— 素材有情绪，但场景没有。

2. **聊天里的 `[表情包:名字]` 至今没有渲染**
   协议早就在 core 里（`llm-agent.ts` 指示模型按 `[表情包:名字]` 发），
   但 console 侧零处理，用户看到的是**纯文本**。

3. **没有管理入口**
   65 张图，看不见有哪些、叫什么、哪些能用 —— 只能翻文件系统。

## 待定（用户 2026-10-03：「先记录一下，先不更新」）

- 是否按场景分组（hero 打招呼组 / 聊天共情组 / 其他）
- 是否加权重或冷却（避免短时间重复、避免总抽到同一张）
- 聊天渲染放在哪一层（消息气泡内联，还是独立气泡）
- 要不要一个「表情包」管理页（看名字、预览、启用/停用）
