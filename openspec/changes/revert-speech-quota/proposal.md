# Change Proposal: revert-speech-quota

## 元信息

- **日期**: 2026-10-25
- **类型**: REVERT（产品判断否决上一轮改动）
- **状态**: applied
- **影响 spec**: `memory-system`（§4.1.7 契约 6.1 改写为「试过、被否决、别再试」）
- **来源**: 用户原话「刚刚改都还是去掉或者先注释吧，**现在的版本就挺好的了其实**」

## 背景：我改了什么，为什么被否

上一轮（`make-speech-quota-beat-persona`）我拿 5 条真实回复做量化，判定"不合格"：

| 指标 | 实测 | 我的判断 |
|---|---|---|
| 平均长度 | 67 字 | 不像发微信 |
| 语气词起头 | 0/5 | 没做到 |
| 语气词密度 | 每句 2–3 个（啦/呢/呀） | 超配额 |

于是把 `soul.md` 语气段改成**配额制**（三样合计最多一处），并在代码块加"优先于人格"的声明。

**用户的判断是相反的**：那个版本（配额改动**之前**、12:26–12:43 的对话）就是他要的样子 ——
她的语气词密度、偏长的回复、'呀/呢/啦' 的温度，**不是缺陷**。

## 需求（做什么）

- [x] `soul.md` 语气段**还原**（句尾常带呀/呢/啦/哦；♪ 可加；偶尔反问）
- [x] `CHAT_BREVITY_DIRECTIVE` **撤掉**两行：「优先于人格的语气描述」「不要复述他说过的话」
- [x] 语气那条从「合计最多一处」改为**无硬配额**：
      「用得自然就好 —— 不必刻意压掉，也别为了人设每句都加」
- [x] 测试改成**反向守卫**：`expect(...).not.toMatch(/合计最多一处/)` ——
      谁也不许再把硬配额加回来（否则她会立刻变干巴）
- [x] 快照更新（文本回退）
- [x] spec 契约 6.1 改写：**记录"试过、被否决、别再试"**

## 关键决策

**为什么不干脆全撤到 10-24 之前**：用户说的是"刚刚改的"（配额那批），
而他称赞的版本本身**包含** `说话的手感` 块（开口先有反应/具体化/素材/允许不完整，11:12 上线）。
那部分保留。

**保留「不必刻意压掉」这半句**：完全无约束的另一个极端是"为了人设每句都加"，
她原本的人设文档里也有这句提醒（"不要为了展示人设而每句话都强行使用「人家」"）。
分寸留着，配额拿走。

**「不要复述他说过的话」虽然撤了，但问题是真的**：真实案例 —— 他说"牛肉丸+鸡蛋+泡面"，
她回"牛肉丸加个蛋，好歹有肉有蛋，比光泡面强多了呀"。这条**想恢复只需加回一行**，
依据与取舍写在代码注释里。
