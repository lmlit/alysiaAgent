# Change Proposal: externalize-life-prompts

## 元信息

- **日期**: 2026-10-01
- **类型**: MODIFY（搬移提示词资产，内容逐字不变）
- **状态**: proposed
- **影响 spec**: `ai-life-system`（提示词资产位置）
- **上游**: `modularize-server-assembly`（P3）

## 动机（为什么做）

`al:life` 的 5 段 systemPrompt（最长一段 2000+ 字）原本内联在 `bootstrap.ts` 的
回调里，与接线代码搅在一起——改一句话要读 330 行。P3 已把它们提成 `modules/life.ts`
顶部的常量；本 change 把它们**搬到专门的资产目录**。

## ★ 与原计划的偏离：不做 `.md` + loader

原 P4 计划是「外置成资源文件」（照 `packages/core/src/persona/` 的做法）。
动手前核对发现**两个方案都要付代价，而收益在本项目站不住**：

### ① 「逐字不变」与「可读」不可兼得

多行提示词在原码里是**无分隔符拼接**：

```ts
'……决定怎么做：' +
'① fulfill=兑现：……' +
```

运行时是 `：①`。放进 `.md` 会变成两行 → 运行时 `：\n①` —— **这是内容变更**。
要么 `.md` 里是一行 2000+ 字的巨型文本（比原码还难读），要么接受提示词多出换行。

### ② 收益没有对应的工作流

外置的卖点是「改提示词不用碰代码」。但本项目**改完仍要重新构建 + 部署 Docker**，
不存在热改场景——省下的只有「打开 .ts 而不是 .md」。

### ③ 新增两类故障面

- 构建要加 `cpSync` 把资源拷进 `dist/`
- 运行时要做路径解析——**正是 `docs/dsh-migration-guide.md` 坑 #2 的同类坑**：
  路径算错 → `existsSync` false → **静默不生效且无报错**

**决定**：改为搬到 `src/prompts/life.ts`（TS 常量，字节不变），
并把上述判断写进 `src/prompts/README.md`——**避免以后反复讨论同一件事**，
同时留下「什么情况下该回头做 `.md`」的判据。

*这是对既定计划的有意偏离，理由记录在此便于对账。*

## 设计决策

**决策 1：搬运用脚本做文本切片，并断言逐字符一致**

手抄提示词有出错风险。用一个一次性脚本按文本切片搬运，脚本内断言
「加/去 `export ` 前缀后与源完全相等」——**通过后才落盘**。脚本跑完即删。

**决策 2：加提示词守卫测试，但只锁「关键约定」不锁全文**

提示词被误删/截断时**不会有任何报错**——编译通过、启动正常、测试全绿，
只是她的行为悄悄变差。这正是本项目反复栽的「静默劣化」。

锁全文会让测试变成复读机（改一个字就要改测试）。所以只锁**它存在的理由**：

| 断言 | 守什么 |
|---|---|
| 长度下界 + 无首尾空白 | 被清空/截断 |
| 要 JSON 的三段必须含 `"json"` | API 硬约束（`json_object` 要求 prompt 含 json，否则 400） |
| **纯文本两段不得要求 JSON** | 反向守卫——配错同样 400 |
| 各段的关键标记 | 历次实测踩坑后补上的约束（真实感 9 条 / 三选一 / 诚实优先…） |
